# 单时钟与 Work/Xfer 契约

所有模型共享一个时钟域，整数物理时间单位 ps，默认周期 1000 ps。只模拟有效上升沿。周期 n 的时间为 n × period_ps，从周期零开始。TimePs 与 CycleCount 为不同类型，转换显式且检查溢出。

平台拥有时钟，模型通过上下文读取 NowPs、CurrentCycle 和周期长度，不可推进或修改平台时间。模型内部延迟计数器不是独立时钟。物理时间参数使用 `_ps`，服务和传输延迟以周期计量。

内核每周期依次执行：**Prepare → 所有模型 Work → Resolve → 所有模型 Xfer → Publish**。Resolve / Publish 保留给通用 ProtocolLink；当前 CHI 系统不注册独立 ProtocolLink，CHI 业务集中在 Prepare、Work 和 Xfer。`System` 在 Prepare 提交负载及消费完成，避免请求产生时刻依赖模型遍历顺序。RN/HN/SN 的端口由各自适配层驱动，不得再由另一条调度路径重复推进。

## Work

适配器先推进所属端口，收集到达消息和上一周期发送确认，再调用核心 `BeginCycle`。核心根据就绪事件推进事务，产生唯一 token 标记的输出动作；适配器尝试将其加入各通道 TX。一个通道背压不阻塞其他通道的完成消息。

核心在 Work 计算工作状态，`InspectLine` 等已提交视图仍保留上一周期状态。资源等待者仅在相关条件变化时唤醒，定时诊断仅处理到期项。核心事件驱动不等于内核跳过空闲周期，端口仍需逐周期推进。

事务工作状态在 `BeginCycle` 中原位推进；`Commit` 发布缓存 / 目录视图、完成、观察记录和内存写入，不是整个核心状态的双缓冲切换，也不支持失败后的推测回滚。异常运行应终止，不能依靠丢弃 Commit 来恢复事务。

## Xfer 与提交

适配器调用端口 `Xfer`，查询 `Transmitted<Flit>()`，记录真实发送 token 与周期，然后调用核心 `Commit` 发布本周期状态、完成记录和观察记录。发送确认在下一周期 Work 才交付给核心；不得把动作生成或 `Send` 成功当作实际发送。

本周期达到就绪条件的输出允许在本周期 Xfer 发送。端口只使用本端队列和此前可用的 credit，不根据其他模型刚提交的业务状态重新决定传输。本周期从对端发送的数据最早下一周期 Work 可见，禁止同周期穿透多个节点。

## CHI 链路

`Send` 在端口 Work 与 Xfer 之间复制 flit 加入本端 TX，返回值表示入队成功。端口 Xfer 根据已有 credit 将队首推送到对端延迟队列，每通道每方向每周期最多一拍。接收端到期 Work 将其移入 RX；`Recv` 出队，空时保持输出不变。

新收到 credit 在本端 Xfer 完成后并入可用计数，下一周期才能使用。CHI 自行维护从零开始的调用周期，不访问平台 Clock。相连端口每周期必须各调用一次 Work/Xfer；HN 有多个端口时，先推进其所有端口再处理核心输入。所有节点必须先完成 Work，再开始任何 Xfer。

REQ/RSP/SNP/DAT 的 TX 深度、RX 深度和 flit/credit 延迟分别通过 C++ API 设置，不使用配置文件。日志和 Trace 由外层模型或 Observer 记录。相同配置、输入和种子应在正反模型遍历下得到相同结果。

## 结束条件与适用范围

模型 IsIdle 包括核心和所持端口的 IsIdle。应用必须消费完成队列，并继续推进直到事务、事件、动作、未交付确认、数据和 credit 全部排空。RN 缓存有效或带脏数据本身不阻止核心空闲；需要检查最终内存时，应用另行发起协议清洁。

`last_time_ps` 表示最后执行的上升沿时间，不是已执行周期数乘周期长度。修改 period_ps 只改变物理时间，不改变按周期计量的协议行为。系统性能数值取决于当前拓扑、缓存状态、流控和工作负载，旧只读链路的周期数不作为当前系统基线。

当前只支持单线程、单时钟和启动复位，不实现运行中复位、下降沿、门控、变频、多时钟域或跨线程同步。
